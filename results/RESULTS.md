# adaptive-ui-runtime — v1 results

**Verdict (matches the data):** deliverable and demonstrated end to end on a real browser.

- Four **structured/deterministic** classes: **every arm 5/5**.
- Two **decision** classes diverge by capability: Jev-capable arms fire Jev once and
  pass 5/5 (`finite_choice_no_steps`); manager-capable arms fire the strong manager
  once and pass 5/5 (`under_specified_stateful`); **`deterministic_only` fails 0/5**
  on both (`unexpected_state`) — the intended fail-closed behaviour of a baseline with
  no route for a non-deterministic task.

- commit: `c044d41` — this is the PR head; the only commits after it are
  results-only regeneration (this file + `benchmark.json`).
- transport `isolated` (real Playwright Chromium, existing binary, no download)
- reps: 5 per arm; n=5 is reported as **min/median/max**, never as a percentile
- generated by `scripts/run_e2e_benchmark.py` (same `Engine` the CLI/MCP call)

## Ablation honesty (self-describing)

**Fara and ShowUI are not exercised by this suite.** The `fara` and `showui` call
columns are printed above and are **0 on every arm of every case** — including the
`no_fara` and `no_showui` arms, which are therefore byte-identical to `adaptive`.
Reason: none of these task classes needs a visual worker (TodoMVC is fully
DOM-addressable). Their inclusion in the runtime is justified by the `local_cua`
PR #16 evidence and the bounded-worker unit tests, **not** by this benchmark. A
visual-only target class is required in a future suite to measure them.

The toggles this suite **does** discriminate: **Jev** and the **manager** —
`deterministic_only` (neither) fails the two decision classes; the Jev/manager-capable
arms pass.

## What the numbers mean

- **Structured classes** (deterministic_dom, multi_step, stateful_dom_eval, recovery):
  all arms 5/5, `manager=0`, `jev=0`.
- **`finite_choice_no_steps`**: Jev fires once on the Jev-capable arms; passes 5/5.
- **`under_specified_stateful`**: the **strong manager fires once** (`manager=1.0`) on
  the manager-capable arms; passes 5/5. **This class costs one manager call** — the
  "0 manager calls" property holds only on the structured classes and on
  `finite_choice_no_steps` (which routes to Jev), not here.
- **Recovery**: `recoveries=1.0` on every arm of the recovery case; the case refuses
  to run on a non-fault-injecting transport (it would otherwise misreport).
- **Loops = 0** everywhere.

## Cost / turns

- Structured classes: 0 manager calls, 0 Jev calls.
- `finite_choice_no_steps`: 1 Jev call/run (vs `deterministic_only` making none and failing).
- `under_specified_stateful`: 1 manager call/run.
- Reused `jev-tests`: Jev decisions ~1.2-1.4 s vs ~2.5-2.6 s GLM; Jev+Playwriter 16.1 s vs
  GLM 27.1 s whole-task (~40% lower). This runtime's Jev path is live-verified.

## Failure classes observed

- `stale_target` -> repaired -> success (all arms of the recovery case).
- `unexpected_state` -> `deterministic_only` on both decision classes (no route).
- Ambiguous multi-match target with no `target_nth` -> fails closed (tests).
- Jev low confidence -> escalate; repeated action -> `repeated_action_loop` (live).

## Explicit supported-task scope (v1)

**Supported:** deterministic DOM tasks with a known structured step sequence; multi-step
structured workflows on a single page; stateful DOM/eval tasks driven by the
structured/manager loop; finite-choice decisions via Jev (fail-closed escalation);
recoverable transport failures via classified bounded recovery on a real browser;
live-site DOM/eval audit tasks (verified on PUMA-UK tag inspection).

**Out of scope:** bare Fara/ShowUI on stateful, multi-item or live-site DOM-truth
workflows (local_cua PR #16); Fara-9B anywhere in v1; Stagehand, and Browser Harness
kept as a dev/debug tool only (#6); verified-recipe cache and native desktop
transports (#19/#20).
