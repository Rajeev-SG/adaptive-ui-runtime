# adaptive-ui-runtime — v1 results

**Verdict (stated to match the data):** the runtime is deliverable and demonstrated end to end on a real browser.

- On the four **structured/deterministic** classes, **every arm is 5/5**.
- On the two classes where a *decision* is required, the arms **diverge by capability**:
  the Jev-capable arms (`adaptive`, `no_fara`, `no_showui`) record `jev=1` and pass 5/5
  on `finite_choice_no_steps`; the manager-capable arms record `manager=1` and pass 5/5
  on `under_specified_stateful`; and **`deterministic_only` fails 0/5 on both**
  (`unexpected_state`) because it has neither Jev nor the manager. That failure is the
  intended fail-closed behaviour of a baseline with no route for a non-deterministic task.

- commit: `a3c59eb` (regenerated at the PR head)
- transport `isolated` (real Playwright Chromium, existing binary, no download)
- reps: 5 per arm; **n=5 is reported as min/median/max**, not as a percentile
- generated by `scripts/run_e2e_benchmark.py` (same `Engine` the CLI/MCP call)

## What the numbers mean (scoped honestly)

- **Structured classes** (deterministic_dom, multi_step, stateful_dom_eval, recovery):
  all six arms 5/5, `manager=0`, `jev=0`; the arms differ only in router fallback scans.
- **`finite_choice_no_steps`**: `adaptive`/`no_fara`/`no_showui` fire **Jev once** and pass
  5/5; `deterministic_only` fails 0/5.
- **`under_specified_stateful`**: `adaptive` fires the **strong manager once**
  (`manager=1.0`) and passes 5/5; `deterministic_only` fails 0/5. **This class does cost
  one strong-manager call** — the "0 manager calls" property holds only on the structured
  classes and on `finite_choice_no_steps` (which routes to Jev), not here.
- **Recovery**: `recoveries=1.0` on every arm of the recovery case and all verify.
- **Loops = 0** everywhere.

## Ablation honesty

- The observable toggles in this suite are **Jev** and the **manager**:
  `deterministic_only` (neither) fails the two decision classes; the Jev/manager-capable
  arms pass.
- **Fara and ShowUI were NOT exercised by this suite.** `no_fara`/`no_showui` are
  byte-identical to `adaptive` on every case because none of these classes needs a visual
  worker (TodoMVC is fully DOM-addressable). Their inclusion is justified by the `local_cua`
  PR #16 evidence and the bounded-worker unit tests, **not** by this benchmark. Measuring
  them needs a genuinely visual-only target class in a future suite.

## Cost / turns

- Structured classes: 0 strong-manager calls, 0 Jev calls.
- `finite_choice_no_steps`: 1 Jev call per run (vs `deterministic_only` making none and failing).
- `under_specified_stateful`: 1 manager call per run.
- Reused `jev-tests` evidence: Jev decisions ~1.2-1.4 s vs ~2.5-2.6 s for GLM; Jev+Playwriter
  16.1 s vs GLM 27.1 s whole-task (~40% lower). This runtime's Jev path is live-verified.

## Failure classes observed

- `stale_target` -> repaired (`recoveries=1`) -> success (all arms).
- `unexpected_state` -> `deterministic_only` on both decision classes (no route).
- Ambiguous multi-match target with no `target_nth` -> fails closed (tests).
- Jev low confidence -> `escalate`; repeated action -> `repeated_action_loop` (live).

## Explicit supported-task scope (v1)

**Supported and demonstrated:** deterministic DOM tasks with a known structured step
sequence; multi-step structured workflows on a single page; stateful DOM/eval tasks driven
by the structured/manager loop; finite-choice browser decisions via Jev (fail-closed
escalation); recoverable transport failures via classified bounded recovery on a real
browser; live-site DOM/eval audit tasks (verified on PUMA-UK tag inspection).

**Out of scope / delegated:** bare Fara/ShowUI on stateful, multi-item or live-site
DOM-truth workflows (local_cua PR #16); Fara-9B anywhere in v1; Stagehand, and Browser
Harness retained as a dev/debug tool only (#6); verified-recipe cache and native desktop
transports (#19/#20).
